# Безопасность «Нити» (версия 6.0)

Этот документ — итог аудита и список мер. Ничего не гарантирует «абсолютную» защиту, но закрывает всё, что нашлось, и описывает, что нужно включить вручную.

## Как устроена защита
1. **База (Supabase)**: у всех 26 таблиц включена защита строк (RLS); каждый запрос проверяется правилами. Личные файлы лежат в закрытых бакетах, доступ — по папке владельца или участникам переписки.
2. **Сайт**: строгая политика загрузки (CSP) — исполняется только свой код (`script-src 'self'`), соединения только с нашими серверами, без `eval`, без встраивания в чужие страницы, ссылки не передают адрес сайта (`referrer: no-referrer`). Чужие библиотеки и шрифт лежат в проекте (`js/vendor`, `css/fonts`), а не подгружаются с CDN.
3. **Тексты сообщений** вставляются как обычный текст (не как HTML), поэтому внедрить скрипт через сообщение нельзя. Ссылки — только `http(s)`, с `rel="noopener noreferrer"`.
4. **Игровые серверы**: подключение только с нашего сайта, личность по токену входа Supabase (имя подставить нельзя), размер и частота сообщений ограничены.

## Что нашёл аудит и как закрыто (supabase/v12.sql)
| Находка | Риск | Исправление |
|---|---|---|
| Получатель заявки в друзья мог менять любые колонки строки | подставить чужой аккаунт в дружбу | триггер: можно только принять заявку, участников менять нельзя |
| Сообщение можно было отправить в личку «через группу» | спам не-друзьям в обход правил | запрещено сочетание «получатель + группа» |
| Нет проверки времени/правки/удаления при вставке сообщения | подделка времени | время и служебные поля выставляет сервер |
| Файл в сообщении — любой путь | чужой файл в своей переписке | допускается только свой или из доступной вам переписки |
| Нет ограничения частоты | спам, перегрузка | лимиты: сообщения, заявки, группы, истории, стикеры, участники |
| Любой мог вызвать `alog` | подделка журнала админов | функция закрыта для телефона |
| Все функции базы доступны без входа | утечка информации | закрыты, остались только `username_free` и `login_alias` (нужны на экране входа) |
| Нет 2FA | кража пароля = взлом | двухфакторная защита (TOTP), проверяется и в базе |
| Картинки по ссылкам грузились сами | отправитель узнаёт IP | загрузка после нажатия (настройка) |
| Подделка карточек подарков и «Премиум-подарка» | обман | карточки проверяются по данным базы |
| Чужие скрипты с CDN | взлом CDN → XSS | библиотеки лежат в проекте |

## Для пользователя (в приложении)
Настройки → **Безопасность**: двухфакторная защита, код-пароль, скрытие экрана при сворачивании, выход на всех устройствах.

## Что нужно включить вручную (я не могу сделать это за вас)
**Supabase → Authentication**
- *Attack Protection → CAPTCHA* (Cloudflare Turnstile, бесплатно): защищает регистрацию от ботов-двойников.
- *Providers → Email*: минимальная длина пароля 10, подтверждение почты включено; *«Prevent use of leaked passwords»* (тариф Pro).
- *Rate Limits*: ограничьте регистрации и письма в час.
- *Multi-Factor*: TOTP должен быть включён (по умолчанию включён) — без этого 2FA в приложении не заработает.
- *URL Configuration*: Site URL = `https://solofse.github.io/nit/`, в Redirect URLs — только этот адрес.
**Аккаунты, которые управляют проектом** (это самое слабое место любой системы): включите двухфакторную защиту на **Supabase, GitHub, Cloudflare, Render**, используйте уникальные пароли или passkey. Взлом любого из них = полный контроль над приложением.
**GitHub**: включите *Branch protection* для `main` и *Secret scanning*.
**Cloudflare**: отзовите доступ Wrangler (My Profile → Access Management), когда не деплоите.
**Резервные копии**: на бесплатном тарифе Supabase автоматических копий нет — периодически выгружайте базу (Database → Backups или `pg_dump`).

## Ограничения (честно)
- Сообщения хранятся на сервере в открытом виде и защищены правилами доступа. **Сквозного шифрования (как в Signal) нет**: это отдельный большой проект.
- Код-пароль защищает от чужих рук на вашем устройстве, но не от человека с доступом к инструментам разработчика в браузере.
- GitHub Pages не позволяет задавать заголовки безопасности: политика загрузки задана через `<meta>`, а запрет встраивания (`frame-ancestors`) обеспечивает скрипт `js/guard.js`.
- Если потерян телефон с приложением-аутентификатором, вход невозможен: Главный админ сбрасывает 2FA в админ-панели (карточка человека → «Сбросить 2FA»).

# Нить — мессенджер

Веб-мессенджер для друзей: личные чаты, группы, фото, файлы, голосовые, кружочки, стикеры, реакции, опросы, мини-игры, голосовые и видеозвонки. Чистый HTML/CSS/JS без сборщиков и фреймворков, бэкенд — **Supabase** (база, вход, хранилище файлов, realtime).

- Сайт: **https://solofse.github.io/nit/** (GitHub Pages, ветка `main`, корень репозитория)
- Репозиторий: https://github.com/soloFSE/nit
- Интерфейс и все тексты — на русском. Пользователь и его друзья — не программисты: объяснять просто, без жаргона.

> Этот файл — «память» проекта для следующего ИИ-агента или разработчика. Обновляйте его, когда меняете что-то существенное.

---

## Быстрый старт для агента

1. Прочитайте разделы «Архитектура» и «Подводные камни» ниже — там то, на чём уже спотыкались.
2. Код — в `js/`, по одному файлу на фичу. Стили — один файл `css/style.css`.
3. Проверять изменения: `node tools/serve.js .` → открыть `http://localhost:5173/__test` (подставная база, вход не нужен). См. «Как проверять».
4. После правок: `node build.js` (пересобирает `dist/nit.html` — версию одним файлом), затем `git pull --rebase` (друг тоже правит репозиторий!) и `git push`. Сайт обновится сам через 1–2 минуты.
5. Если изменение требует новых таблиц/полей — **напишите отдельный SQL-файл в `supabase/`** и попросите пользователя выполнить его в Supabase → SQL Editor. Сами вы в базу не попадёте. Код должен **работать и без нового SQL** (деградировать мягко, с подсказкой «запустите supabase/xxx.sql»).

## История проекта (кратко)

1. Друг пользователя сделал в Claude P2P-мессенджер «Нить» на WebRTC/PeerJS одним файлом `index.html`.
2. Затем его переписали на **Supabase** (аккаунты по нику, друзья, сообщения, фото) — всё ещё одним файлом.
3. В этом чате:
   - файл разделён на `index.html` + `css/style.css` + модули в `js/`;
   - починена «залипающая» кнопка принятия заявки в друзья (гонка запросов + перерисовка под пальцем);
   - добавлены: голосовые → группы → профиль и новый дизайн → кружочки → блокировка, смайлики, стикеры, реакции, ответы, «в сети», «печатает…» → большое обновление (прочитано, редактирование, пересылка, закреп, поиск, файлы, ссылки, опросы, игры, анимации, свои стикеры, исчезающие сообщения, обои/цвет, статус, инфо группы, звонки, уведомления, PWA, черновики);
   - **оптимизация**: опрос сервера был каждые 2 с (≈100 запросов/мин на вкладку) — стало ≈9/мин; подписи ссылок на файлы пачкой; меню сообщений строятся лениво; кружки играют только на экране;
   - история чата больше не «исчезает» при ошибке загрузки (повтор + понятная ошибка); после обновления страницы открывается последний чат;
   - проект выложен на GitHub (`soloFSE/nit`) и GitHub Pages;
   - групповые звонки; плавность: склейка сообщений, даты, кнопка «вниз», жесты, мгновенная отправка, выезжающие экраны на телефоне, плавные окна.

## Архитектура

### Без сборки, обычные `<script>`
Файлы подключаются в `index.html` обычными тегами `<script src>` (не ES-модули) — так сайт работает и с GitHub Pages, и **двойным кликом по файлу** `dist/nit.html`. Следствия:

- Все `const/let/function` на верхнем уровне — **общие глобальные** имена для всех файлов. **Имена не должны повторяться** между файлами (однажды `sig` в `calls.js` совпал с `sig` в `config.js` и сломал звонки). Проверка: см. «Как проверять».
- **Порядок скриптов важен**: код, который выполняется сразу при загрузке файла, может использовать только то, что объявлено в файлах выше. Функции из файлов ниже можно вызывать внутри обработчиков (к моменту вызова всё уже загружено). `app.js` — последним.
- Порядок сейчас: `config, profile, auth, friends, groups, chat, ux, files, reads, compose, voice, circle, social, emoji, reactions, msgtools, fun, appearance, calls, gcall, bg, ginfo, account, inbox, sync, pwa, app`.

### Особые сообщения (`SPECIAL`)
Стикеры, опросы, игры, звонки хранятся **в обычном поле `body`** сообщения со служебным префиксом `::тип…::`. Каждый модуль регистрирует себя:
```js
SPECIAL.push({re:/^::dice:([1-6])::$/, cls:'game-m', forward:false,
  preview:x=>'🎲 Кубик: '+x[1], render:(m,d,x)=>{ /* рисует в d */ }});
```
Форматы: `::st:<код noto>::` стикер, `::cs:<путь>::` свой стикер, `::poll::{"q","o":[..],"m":bool}`, `::dice:N::`, `::coin:0|1::`, `::rps:0-2::`, `::ttt::{"b":"---------","t":"x","x":id,"o":id|"","w":""}`, `::call:<сек>:<0|1 видео>::`, `::gcall:<uuid звонка>:<0|1>::` групповой звонок, `::ttl:<сек>::` включение/выключение исчезающих сообщений в чате (0 — выкл), `::slike::` «нравится ваша история», `::title:<id>::` грамота о звании.

**Иконки вместо эмодзи.** В интерфейсе нет эмодзи — только рисованные символы `#i-…` (tools/icons.py). В строках-превью иконка кодируется `PI('i-film')+'Видео'`, выводится через `fillRich(узел, строка)`, для системных уведомлений — `stripIcons()`. Значок рядом с текстом — `ico('i-…')`.

**Клавиатура на iPhone (ux.js).** Пока поле в фокусе, `.app` = видимая область (`--app-h`, `--vv-top`), подгонка каждый кадр ~1,2 с после фокуса/ресайза. Без фокуса `--app-h` снимается (100dvh) и страница прокручивается к верху — иначе шапка оставалась обрезанной. Обычный текст, начинающийся с `::`, редактировать нельзя (защита в SQL `edit_message`).

### Медиа по `image_path`
Одно поле `image_path` для всех файлов в хранилище `photos`, тип определяется по пути (проверять в этом порядке!):
1. `…/file_<uuid>_<размер>__<имя>` — документ (`isFile`)
2. `….circle.webm|mp4`, с длительностью в имени `_<сек>s` — кружок (`isCircle`)
3. `.webm/.ogg/.mp4/.m4a` — голосовое (`isAudio`)
4. остальное — фото (JPEG, сжимается до 1600px)

### Ключи чатов
- В коде: личка = id друга, группа = `'g:'+id`. Хелперы `isGroupKey`, `gidOf`, `chatKey(m)`, `target(k)` (поля «кому» для вставки).
- В базе (прочитано, закреп): `'dm:<id1>:<id2>'` (id по алфавиту) или `'g:<id>'` — `readKey(k)`.

### Синхронизация
- Основной путь — **realtime** (`postgres_changes`) в каналах `nit` (сообщения, друзья, группы), `nit-reacts`, `nit-more` (прочитано, закреп, голоса). Дополнительные таблицы — **в отдельных каналах**, чтобы отсутствие таблицы (не запущен SQL) не ломало основной.
- `tick()` — **только подстраховка**: раз в 20 с при живом realtime, раз в 5 с без него, ×4 реже в свёрнутой вкладке. Раз в минуту сверяет друзей/группы/реакции, раз в 5 минут — профили. **Не делайте опрос чаще** — это уже однажды положило всё (лаги, не входило с телефона).
- «В сети» и «печатает…» — канал `nit-live` (presence + broadcast). Звонки — broadcast-каналы `call-<id пользователя>`.

## Подводные камни (уже наступали)

- **Глобальные имена** между файлами не должны совпадать (см. выше).
- **Не опрашивать сервер часто** и не делать по запросу на каждый элемент — использовать пачки (`createSignedUrls`) и realtime.
- **Не пересоздавать список под пальцем**: `loadFriends/loadGroups` перерисовывают, только если данные изменились (`frSig/grSig`), и отбрасывают устаревшие ответы (`frSeq/grSeq`). Иначе кнопки «теряют» нажатия.
- **Ошибки показывать, а не глотать**: пустой результат из-за ошибки выглядел как «история пропала».
- Chrome не пишет длительность в webm из MediaRecorder → длительность кружка хранится в имени файла.
- Анимации: новые пузыри анимируются только при живом поступлении (`placed()`), история рисуется пакетно (`bulk=true`) — иначе тяжело и «прыгает». Учтён `prefers-reduced-motion`.
- Прокрутку «внизу ли человек» меряем в момент вставки (`line()` → `near`), а не только по событию scroll.
- Один битый message не должен ломать ленту — `draw` обёрнут в try/catch в `line()`.
- На компьютере пользователя Git уже вошёл в аккаунт **soloFSE** (Git Credential Manager). Пушить в другие аккаунты не получится без их входа; глобальная подпись коммитов — `soloFSE <gaeldar398@gmail.com>`.
- Друг — соавтор репозитория и может править прямо на GitHub: **перед пушем всегда `git pull --rebase`**.
- `dist/nit.html` (файл для пересылки) не умеет PWA и может не получить микрофон/камеру в некоторых браузерах — лучше давать ссылку на сайт.
- Звонки без TURN-сервера: в строгих сетях (часть мобильных операторов, корпоративный Wi-Fi) могут не соединиться.
- **Постоянный вход.** Сессия Supabase хранится в localStorage (`sb-…-auth-token`). Экран входа показывается только если сохранённого входа нет или человек сам нажал «Выйти» (`byUser`). Если при запуске нет сети и библиотека не смогла продлить вход — заставка `#splash` «Подключаюсь…» и повторы `waitSession()` (app.js), а не экран входа. Ошибка загрузки после входа — тоже заставка с автоповтором.
- **Фон и уведомления — ограничения браузера.** На Android звонок в фоне работает (звук держит страницу «живой»), видео с камеры в фоне останавливает сама система. На iPhone браузерам в фоне микрофон отключается — обойти нельзя. Уведомления приходят, пока приложение свёрнуто, но не закрыто полностью: для уведомлений при закрытом приложении нужен Web Push (ключи VAPID + серверная функция Supabase) — не сделано.
- **iPhone и клавиатура.** Safari на айфоне при открытии клавиатуры не уменьшает страницу, а сдвигает *видимую область* (`visualViewport.offsetTop`). Поэтому при касании экрана `.app`, `.modal` и `.auth` закреплены (`position:fixed`) и подгоняются под неё: `ux.js` пишет `--app-h` и `--vv-top`, а `theme.css` (блок «iPhone и iOS») ими пользуется. Шрифт полей на касаниях — 16px (меньше — iOS приближает страницу). Не возвращайте `height:100%` для `.app` на телефоне.
- **Окно «Новый чат».** Блок `#newbox` (добавить друга / новая группа) показывается в `openModal`: его *переносят* в окно, а не копируют — обработчики привязаны к его элементам по id. `stashNew()` (inbox.js) возвращает блок на место перед очисткой окна; любой код, который стирает `#sheet` вручную, должен сначала вызвать `stashNew()`.
- **Голосовые на iPhone.** `play()` работает только сразу после нажатия, поэтому ссылка на файл запрашивается заранее (`voiceEl`). Записи в webm iOS ниже 18.4 не проигрывает — показывается подсказка.
- Пересланные фото могут не открыться у получателя, если правило хранилища `photos` (созданное до нас) пускает только участников исходного чата — не проверено. «Удалить у всех» оригинала копии больше не ломает (`file_in_use`).

## Идеи на будущее
- TURN-сервер для звонков; для групп больше 6–8 человек нужен медиасервер (SFU) вместо «сетки».
- Push-уведомления, когда сайт закрыт (Web Push через service worker + Supabase Edge Function).
- Превью любых ссылок (нужен свой серверный прокси — сторонним сервисам ссылки пользователей не отдаём).
- Сжатие видео-кружков сильнее, предпросмотр перед отправкой.
- Перенос оставшихся «старых» таблиц в миграции, чтобы базу можно было поднять с нуля.

## Работа в России без VPN (посредник)
- Адреса `*.supabase.co` в России блокируются. Все запросы могут идти через **Cloudflare Worker** `https://nit-proxy.mreldar-work.workers.dev` (аккаунт Cloudflare: mreldar.work@gmail.com, воркер `nit-proxy`). Код — `tools/cloudflare-worker.js` (пересылает /auth, /rest, /storage, /realtime (WebSocket), /functions; `/__nit` — проверка «жив»; остальное 404). Обновлять: Cloudflare → Workers & Pages → nit-proxy → Edit code → вставить → Deploy.
- `js/config.js`: `SUPA_DIRECT` / `SUPA_PROXY`, выбранный путь в `localStorage['nit-route']`. `probeRoute()` при запуске: напрямую не отвечает, а посредник отвечает → переключается и перезагружается (не чаще раза в минуту). `storageKey` клиента фиксирован (`sb-lojlwcsqbbthmpetmbmq-auth-token`), чтобы при смене пути не терялся вход.
- Библиотека Supabase лежит на сайте: `js/vendor/supabase.min.js` (CDN в России тоже бывает недоступен). `tools/serve.js` подменяет её на `tools/mock.js` для /__test.
- Ссылки в письмах ведут на сайт: `{{ .SiteURL }}?token_hash={{ .TokenHash }}&type=signup|email|recovery|email_change|invite`; `js/auth.js` подтверждает их через `verifyOtp` по работающему пути. Шаблоны в Supabase уже переключены.
- Ограничение: вход через Google/GitHub возвращает на `…supabase.co/auth/v1/callback` — без VPN из России, скорее всего, не сработает (исправить можно только платным «custom domain» Supabase). Почта/ник и код из письма работают.
